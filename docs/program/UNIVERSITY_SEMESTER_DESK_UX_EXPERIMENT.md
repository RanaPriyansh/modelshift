# University semester desk UX experiment

**Status:** preregistered final synthetic product-shape loop

**Date:** 31 July 2026

**Surface under test:** internal
`/internal/university-semester-desk`

**Claim ceiling:** method and candidate harness only; no student demand,
learning, accessibility, institutional, selection, recommendation, efficacy,
or production result

## Atomic research question

> After scanning four distinct synthetic course states, can an adult student
> explicitly choose one course to inspect more closely and then clear that
> inspection without believing FORGE selected, prioritized, started, saved, or
> changed the course?

This is the single-surface composition of “all current courses shallow, one
course deep.” It tests learner-directed inspection grammar. It does not choose
what the student should study.

## Fixed harness

Following the useful fixed-loop constraint in
[Karpathy's autoresearch](https://github.com/karpathy/autoresearch), preserve
the fixture, questions, state taxonomy, viewport checks, and authority
boundaries while changing one presentation variable at a time. A person is not
one optimization metric: scan accuracy, inspection-choice meaning, term/course
separation, order calibration, trust, learner control, access barriers, and
harm remain separate observations.

Every comparable run keeps:

- one synthetic adult owner, tenant, term, `asOf`, term label, and time zone;
- four synthetic courses inside one exact Recovery envelope;
- one canonical semester overview and one canonical semester-loop result per
  exact course;
- course-ID order explicitly labelled as not priority;
- no initial course selection or highlighted default course;
- one native scenario radio group and one native course-inspection radio group;
- one clear-inspection control visible only after learner choice;
- exactly one polite live region shared by scenario and inspection changes;
- no summed course-local capacity;
- no global next action, recommendation, score, progress, ranking, workload
  estimate, course activation, or saved preference;
- no live learner, account, coursework, provider, model, retrieval, database,
  browser storage, session start, evidence write, schedule, or message;
- visible authority rows for order basis, caller-asserted identity, tenant
  isolation, rights enforcement, institutional completeness, refresh-clear
  inspection selection, and every denied effect;
- four closed scenarios: mixed term, term source review, capacity choice, and
  World changed; and
- the same desktop, exact 320 CSS pixel, keyboard, focus, reduced-motion,
  forced-colors, overflow, console, production-denial, and public-asset gates.

Changing the course count, raw child inputs, canonical projectors, initial
no-selection state, state taxonomy, order basis, or authority boundary creates
a new baseline.

## Student job

> Let me see the whole term, choose where I want to look closer, and understand
> that course's bounded current job without pretending the system chose for me.

The default mixed-term fixture preserves this hierarchy:

1. synthetic and no-effect boundary;
2. exact term context;
3. whole-term shallow-inspection statement;
4. separate term Recovery status;
5. one continuous course ledger in course-ID order;
6. no preselected course;
7. one learner-chosen course inspection;
8. its Sources, Today, Recovery, Protected Study, and Return journey;
9. one current-job explanation and evidence boundary;
10. clear-inspection control; and
11. authority ceiling.

## Fixed initial and selected states

### Initial

- the mixed-term scenario is checked;
- all four courses are visible;
- no course-inspection radio is checked;
- no deep-course panel or clear control is present;
- the page states that course order is not priority; and
- the live region contains only one bounded initial announcement.

### After explicit course inspection

- exactly one course-inspection radio is checked and remains focused;
- no other course changes position, emphasis, or status;
- the detail panel names only that course's server-authored journey and current
  bounded job;
- the page states that the course was chosen by the learner for inspection,
  not selected or prioritized by FORGE;
- no action is started or offered; and
- clearing removes the detail and returns focus to the previously chosen radio.

Changing scenario clears course inspection. Returning to a prior scenario does
not restore it. Refresh returns to mixed term with no course inspected.

| State | Exact system behavior | Visible inspection boundary |
| --- | --- | --- |
| Mixed term | Term Recovery produces a draft; four course loops remain distinct | Learner may inspect any one course without starting it |

## Fixed comprehension and operation tasks

Only after participant authority is separately approved, use a fixed
25-second initial scan and ask:

1. How many current courses are visible?
2. Which course did FORGE select for you before you acted?
3. What determines the row order?
4. Does “ready for inspection” mean the semester is ready or feasible?
5. Choose one course to inspect. What changed?
6. Did that inspection start, prioritize, save, or schedule the course?
7. What does the five-part journey say about the current bounded job?
8. Clear the inspection. What remains?
9. Change scenario. Was the course inspection retained?
10. Does any copied source count as official university truth?
11. Does anything create a session, message, event, or evidence?

Record each answer as correct, incorrect, or uncertain and retain the
participant's own wording only under the approved capture schema. Separately
record time to name all course boundaries, time to make an inspection choice,
row-order reversals, attempts to find a recommended course or global CTA,
mistaken whole-semester readiness, attempts to start or save, clear-state
errors, focus loss, access barriers, and distress or judgment language.

## Hypotheses

| ID | One variable changed | Expected evidence | Keep condition |
| --- | --- | --- | --- |
| `H01` | Start with no course selected | Learner ownership is legible before any detail appears | Zero participants say FORGE chose the initial course |
| `H02` | Lead with “See the whole term. Choose where to look closer.” | Scan and explicit inspection remain distinct jobs | At least 80% scan all rows before describing one detail |
| `H03` | Label every course control “Inspect this course” | Choice is read as view state rather than activation | Zero participants say the radio starts, enrolls, or prioritizes a course |
| `H04` | Keep equal row/control treatment in course-ID order | Availability color does not become recommendation | Zero participants call the first or teal course recommended |
| `H05` | Keep the term boundary visible while detail opens | Deep inspection does not erase term context | At least 80% still distinguish term Recovery from course status |
| `H06` | Show the five-part journey before current-job copy | The bounded job is understood in process context | At least 80% name the current stage without calling later stages complete |
| `H07` | Use one explicit clear-inspection control | Learner can reverse view state without losing term context | Every participant who opens detail can clear it and explain that no course data changed |
| `H08` | Clear inspection on scenario change | Closed scenario provenance remains legible | Zero participants believe detail silently transferred between scenarios |

## Separate evidence and stop signals

| Dimension | Keep signal | Repair or stop signal |
| --- | --- | --- |
| Course scan | Names every visible course and exact bounded state | Misses a row or merges course states |
| Inspection meaning | Calls the choice a closer view | Calls it priority, enrollment, assignment, activation, or recommendation |
| No-preselection | Says no course was chosen initially | Identifies first, teal, or ready row as FORGE's choice |
| Term/course separation | Keeps Recovery term-wide and journey course-local | Treats one course detail as the complete term plan |
| Order calibration | Says course-ID order is not priority | Infers urgency or value from row position |
| Readiness boundary | Calls inspectable weaker than ready or feasible | Calls semester/course/learner ready, on track, or complete |
| Learner control | Opens and clears one detail predictably | Expects persistent selection or cannot recover the no-selection state |
| External effects | Predicts no save, event, message, provider, or persistence | Expects durable progress or university contact |
| Access | Operates scenario, course, and clear controls at desktop and 320px | Focus, clipping, target size, reflow, or announcement blocks the task |
| Emotional safety | Describes bounded course states without shame or rank | Reads the desk as ability judgment, punishment, or permanent deficit |

Do not average these dimensions into one score. Selection confusion, harmful
ranking, authority confusion, or access failure can veto a visually successful
change.

## Visual target

`docs/design/university-semester-desk-concept.png` is the design basis. It
preserves the established light Vanishing Instrument system:

- warm paper surface and near-black ink;
- deep cyan for exact inspectable state;
- amber for choice or recovery, always paired with text;
- editorial display type, monospace labels, and thin ruled structure;
- one continuous term-to-course-to-job reading order;
- no illustration, chat, dashboard cards, decorative score, or progress ring;
  and
- desktop hierarchy that becomes one semantic vertical reading order at exact
  320 CSS pixels.

The concept's pictured selected course demonstrates the expanded state. The
implemented initial state must still have no course preselected. The concept is
not implementation, accessibility, or participant evidence.

## Automated and rendered gates

- exact server-authored fixture derived from canonical overview and course-loop
  outputs;
- no raw request, World, source IDs, path IDs, receipt, child projection,
  digest, projector, or command in the client fixture;
- no initial checked course radio, selected-course styling, deep detail, or
  clear control;
- native scenario and course radio keyboard behavior;
- scenario changes clear the inspected course;
- clear returns focus to the previous course radio and removes detail;
- exactly one polite live region;
- no storage, cookie, URL, history, clipboard, network, session, persistence,
  event, message, evidence, provider, or external effect;
- no ranking, recommendation, course activation, global action, score,
  progress, workload sum, or feasibility claim;
- desktop and exact 320 CSS pixel reading order, at least 44 CSS pixel targets,
  stable focus visibility, and no horizontal overflow;
- reduced motion, forced colors, console review, exact production denial, and
  public-static-asset scan.

Automation is implementation evidence, not participant comprehension,
assistive-technology evidence, WCAG conformance, learning evidence, or
efficacy.

## Final-slice and promotion gate

This is the final planned synthetic product-shape iteration. After its
implementation checks pass, the next action is approved Phase -1 direct
research, a repair/narrowing grounded in that research, or stopping the wedge.
Do not respond to absent participant authority by building another speculative
surface.

A live semester desk requires approved adult identity and data authority,
complete course-set authority, owner-scoped persistence, tenant isolation,
edit/undo and conflict semantics, trusted source and institution boundaries,
learner challenge and correction, responsible-human routing,
session/evidence continuity, export/correction/deletion, incident operations,
manual assistive-technology review, direct participant evidence, and a
separate release decision.
