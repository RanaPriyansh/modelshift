# FORGE visual direction decision

Decision date: 2026-08-03

Selected direction: **Editorial Terrain Recovery**

Product direction: `amend_to_semester_desk_v2`

## Decision

Use a vivid threshold and a quiet work surface.

Use editorial scale to help the student enter or recover.

Use a flat semester ledger when the student reviews work.

Show all recovery changes before confirmation.

Give the student one selected action for focused study.

Use the same product terms across the website, web application, and native iOS application.

Do not copy a generated interface image into the product.

## Scoring method

Each value uses a five-point scale.

`5` is the strongest result.

The columns use these names:

- Taste: Pri taste fit
- Clarity: product clarity
- Calm: emotional calm
- Distinct: intelligence and distinctiveness
- Hierarchy: information hierarchy
- Mobile: mobile use
- Access: accessibility
- Web: web feasibility
- iOS: SwiftUI feasibility
- Coherence: cross-platform coherence
- Original: resistance to generic AI output

## Round 2 result

The Round 2 board confirms one coherent system.

The public website uses an editorial recovery narrative.

The web application uses a semester ledger, a recovery review, and a focused work surface.

The iOS application uses native navigation, lists, sheets, alerts, and a tab bar.

The visual system uses warm ivory, forest, cobalt, and scarce learner orange.

The visual system uses large grotesk type on web and SF Pro on iOS.

The visual system uses art only at entry, recovery, or delayed return.

## Required implementation rules

1. Use real semantic web components.
2. Use real native SwiftUI components.
3. Keep active study surfaces free from scenic art.
4. Show capacity as hours and minutes.
5. Preserve the student's authored semester order.
6. Show all recovery changes before confirmation.
7. Use learner orange only for a deliberate student choice.
8. Use `Checked`, `Needs review`, `Changed since last check`, and `Not yet confirmed`.
9. Use `Ready to work on` and `Come back on this date` for action states.
10. Support 320 px web reflow and Dynamic Type on iOS.
11. Support keyboard use, VoiceOver order, reduced motion, and forced colors where applicable.

## Generated details that are not approved

Do not use generated product copy as authority.

Do not use generated screenshots on the public website.

Do not use the generated `I have an account` action until online identity exists.

Do not claim cloud sync or university integration.

Do not claim reminder delivery on web.

Do not use a score, percentage, rank, streak, or progress ring.

Do not use landscape art behind active study, proof, course review, or settings.

## Completion test

A final surface passes this decision when:

- A student can identify the current semester state.
- A student can see each changed item.
- A student can state real capacity.
- A student can choose one action.
- A student must do the learning work.
- A student can return later to check retention.
- The surface feels calm during work.
- The surface feels vivid only at a meaningful threshold.
